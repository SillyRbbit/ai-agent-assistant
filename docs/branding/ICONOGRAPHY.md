# Cortexa iconography

## System icons

Use familiar platform-native symbols or the repository's established icon
library when one is already available. Do not add an icon dependency during a
branding-only change. Prefer a symbol to a rounded text control for familiar
actions such as close, back, save, download, zoom, or formatting.

Use a consistent 24 px design grid for general interface icons, with stable
button dimensions and a consistent optical stroke weight. Keep icons simple,
front-facing, and recognizable at the target size. Provide a text label or
tooltip when meaning is not universally familiar.

## Product mark

The Cortexa brain-and-circuit logo is an identity mark, not a general-purpose
interface glyph. Do not use fragments of it for navigation, status, bullets,
tool icons, loading states, or decorative patterns. Use `favicon.png` for the
smallest approved identity contexts and `app-icon-source.png` only in the
separate verified application-icon workflow.

## Color and state

Use neutral icon colors by default and Core Blue for a selected or primary
state when contrast passes. Use established semantic colors for success,
warning, and error. Never recolor the product logo to indicate state, risk, or
permission.

## Review

Confirm that every icon has a stable container, remains legible in light and
dark modes, does not shift layout on hover, and has an accessible name when the
button has no visible text.
