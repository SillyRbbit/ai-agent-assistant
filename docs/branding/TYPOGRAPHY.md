# Cortexa typography

## Approved stacks

Use fonts already available on supported operating systems. Do not add a web
font or font package solely for branding.

Product and documentation sans-serif stack:

```css
font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", Arial, sans-serif;
```

Code and identifiers:

```css
font-family: "SFMono-Regular", Consolas, "Liberation Mono", monospace;
```

## Hierarchy

- Product name and page title: 600-700 weight, sentence or title case.
- Section heading: 600-700 weight with compact spacing.
- Body and operational labels: 400-600 weight, optimized for scanning.
- Metadata and captions: smaller than body text but never below the product's
  accessible minimum.
- Code, commands, paths, and identifiers: monospace only where the literal
  distinction matters.

Use size, weight, spacing, and placement to establish hierarchy. Do not scale
font size directly with viewport width. Keep letter spacing at `0`; do not use
negative tracking. Avoid all-uppercase body copy. Use uppercase only for short
diagram lanes or compact category labels where the established layout supports
it.

## Executive materials

Use direct, decision-oriented headlines and short supporting text. Prefer one
claim per slide or section. Tables and diagrams should be readable at normal
presentation distance without oversized decorative typography. Do not use
display fonts, condensed novelty faces, or handwritten styles.
