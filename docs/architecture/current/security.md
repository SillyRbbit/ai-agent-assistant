# Security evidence and limits

This is a bounded architecture assessment from code and retained QA, **not a complete
security audit**. No private credentials, profiles, databases, live processes or raw
provider payloads were inspected. A system prompt and bot title are not enforcement.
A directory or Git worktree is not automatically a security sandbox.

## Data that can leave the machine

The owner message, canonical role, saved identity/personality/instructions, accepted
completed history, and opted-in private note go to the selected chat provider.
Collaboration sends the objective, explicit sources, participant settings and validated
prior handoffs; private notes are excluded. Native model discovery is a separate explicit
metadata request. API headers carry credentials only in native transport. Codex reads its
dedicated native credential store and talks to its authenticated service; the WebView
receives no account tokens. LM Studio/Ollama traffic is loopback at Cortexa's boundary,
but the server's downstream behavior is not established. `store=false`, ephemeral thread flags and a Stop button do not prove provider retention
is zero. The two credential/account routes must remain explicit; never infer API funds
from a Codex/Work balance. No personal credential path or value is embedded here.

## Important gaps, without speculative repairs

1. **Content-level prompt injection remains possible.** Context is labeled untrusted,
   authority is constrained, and handoffs are validated. There is no proof that a model
   cannot follow malicious document text or produce misleading advice.
2. **No live apply-changes agent.** Closed foundations and advisory QA/Security roles
   must not be drawn as a functioning repository executor, approval-to-patch pipeline,
   scheduler, cloud operator or browser automation service.
3. **Local custody remains owner-dependent.** Application directories have Unix owner
   permissions; SQLite encryption, secure erasure and automatic backups are not established.
4. **Codex isolation is bounded.** Reviewed handshake/configuration and native reaping
   are evidenced. Same-user compromise, arbitrary runtime updates and OS-level containment
   are outside this assessment.
5. **Export partial-file risk is visible from code.** Refusing overwrite protects an
   existing destination, but does not make a multi-byte new-file write transactional.
6. **Retained audit advisories are unresolved.** Passing accepted-baseline CI is not a
   claim of vulnerability-free dependencies. Broad live runtime/model/route combinations
   and production signing/distribution remain unverified or deferred.

None of these limitations is repaired or waived by a diagram. They inform a separately
scoped future review if the owner chooses one.
